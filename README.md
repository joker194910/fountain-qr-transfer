# fountain-qr-transfer
# Fountain QR Transfer

纯前端单页循环二维码文件传输实现（文件上限 5MB）。

## 技术细节

### 1. 分块与块组校验预编码
- 输入文件（单文件或自动打包的 `.zip`）经字节切分为 $k$ 个等长原始数据块 $S_0, S_1, \dots, S_{k-1}$（末尾不足块长补零，原始字节长度在帧头记录）。
- 在 $k$ 个原始块基础上，按固定步长/交织规则生成约 10% 的校验块 $P_0, P_1, \dots, P_{m-1}$（每组若干原始块做按位 `XOR`），组成符号池。
- 译码端收到已知原始块后，同步代入对应校验组方程；当某校验组剩余未知原始块数为 `1` 时，直接异或消元得出该块，降低收尾长尾开销。

### 2. LT 喷泉编码与译码
- **PRNG 与种子**：发送端帧序号 `seed` 线性递增（`1, 2, 3...`），由确定性伪随机数生成器（`Mulberry32`）基于 `seed` 派生度数 $d$ 与不重复参与块索引集合，帧内仅携带 `seed` 而非完整索引列表，接收端按相同 `seed` 还原方程结构。
- **度分布**：采用鲁棒孤子分布（Robust Soliton Distribution）采样度数 $d$，兼顾度 `1` 初始解注入、中等度数链条传导与少量高阶覆盖。
- **BP 迭代译码**：接收端维护已知原始块集合与未解多元 `XOR` 方程缓冲池；每次解出新块后，对包含该块的方程执行 `XOR` 消元并降阶，直至全部 $k$ 个原始块还原并通过整体校验。

### 3. 帧结构、扫码与进度统计
- **帧封装**：二进制帧头包含协议标识、文件元信息/总大小/分块数 $k$、全局校验值、`seed`、载荷及帧级校验，编码为文本后渲染为 QR Code。
- **扫码识别**：优先调用 `BarcodeDetector`，不可用或失败时回退至 `jsQR` 解析视频帧。
- **进度与 ETA**：进度严格按 `已解出原始块数 / k` 计算，暂存多元方程单独计入“缓存方程数”；ETA 基于滑动窗口有效收帧速率与剩余未知块估算。
- **布局与权限**：视口适配锁定 `100dvh` 兼容 1080p 及缩放屏幕；`getUserMedia` 需运行在安全上下文（`HTTPS` 或 `localhost`），并在 `facingMode` 受限时逐级降级请求。

## 使用方法

1. 将单页 HTML 文件（建议命名为 `index.html`）部署至支持 `HTTPS` 的静态托管或通过 `http://localhost:<port>` 本地服务打开。
2. **发送端**：选择 `≤ 5MB` 文件或文件夹/多文件，选择预设档位后开始循环播放二维码；可使用单机丢包回路测试验证编解码。
3. **接收端**：开启摄像头对准发送端屏幕连续扫码，等待进度达到 `100%` 并通过完整性校验后下载还原文件。
